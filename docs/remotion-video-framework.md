# Remotion Video Framework
# When you say "let's make a Day 100 milestone recap" or "let's do that Deut 28 prophecy series

A reusable pattern for producing branded videos via Remotion (programmatic React-based video composition + render-to-MP4). First proven on the Faith Walk Live anchor documentary 2026-05-07; intended for every future video on this channel.

**Tooling:** Remotion 4 + faster-whisper + gpt-image-1 + the existing OpenAI/Anthropic API setup.

---

## When to use this framework

| Scenario | Use Remotion? |
|---|---|
| 10+ minute long-form documentary, scripted, multiple clips + cards + narration | ✅ Yes |
| Recap reel from existing footage (60-90s, branded crossfades) | ✅ Yes — see `create-highlight-reel` skill |
| All-graphics topic reel from a topic prompt (no source footage) | ✅ Yes — see `create-reel` skill |
| Single-clip video with one logo overlay | ❌ No — overkill, use CapCut/Canva |
| One-off social Short cut from existing footage | ❌ No — Canva/CapCut is faster |

The break-even: if a video has scripted narration + multiple clips + branded text overlays + you'll likely iterate it 2+ times, Remotion pays off. Otherwise click-edit.

---

## The pipeline (proven on the anchor doc)

```
Narration MP3s (TTS)  ─┐
Source clips           ─┤
Brand title cards      ─┼──▶  Remotion composition  ──▶  MP4 1920×1080 30fps
Whisper subtitles      ─┤
(optional music bed)   ─┘
```

**5 inputs go in. 1 file comes out.** Re-rendering after a change takes ~30-50 minutes for a 13-minute video; iteration is fast.

## ⚠️ Pre-flight checklist (do these BEFORE you write any composition code)

**Skip these and you'll burn an hour on bugs that show up only at minute 10 of a 30-minute render.** We hit both on the anchor doc v1.

### 1. Probe every asset's actual duration

```bash
# Narration MP3s — duration in seconds, via mutagen
python -c "
from mutagen.mp3 import MP3
import glob, os
for f in sorted(glob.glob('PATH/TO/audio/*.mp3')):
    print(f'{os.path.basename(f):40s} {MP3(f).info.length:6.1f} sec')
"

# Source video clips — pre-existing TSV in faith-walk-live/anchor-doc/clip-durations.tsv,
# or generate fresh via:
python -c "
from mutagen.mp4 import MP4
import glob, os
for f in sorted(glob.glob('PATH/TO/clips/*.mp4')):
    try: print(f'{os.path.basename(f):60s} {MP4(f).info.length:6.1f}s')
    except: pass
"
```

**Why:** Remotion's `<OffthreadVideo>` will silently freeze on the last frame if you ask for a duration longer than the source. The frozen frames render fine — you only notice on playback. v1 froze 4.5s on a 10.5s clip we asked for 15s. Probe first; size your `duration` to never exceed source.

### 2. Tile narration contiguously, not by shot list timestamps

Shot lists are written assuming continuous narration. Real TTS MP3s have variable lengths. v1 had a 70-second silent gap between Beat 2 narration ending and Beat 3 narration starting because the shot list said "Beat 3 at 7:08" but Beat 2 narration only ran from 4:35-5:57.

**Fix:** sum your narration durations first, then place each one to start where the previous one ended (plus any intentional silence at cards or transitions). Don't trust shot-list timestamps blindly.

### 3. Confirm asset paths resolve

```bash
ls PATH/TO/public/audio/  # must contain every MP3 referenced in NARRATIONS
ls PATH/TO/public/clips/  # must contain every clip referenced in CLIPS
ls PATH/TO/public/cards/  # must contain every card PNG
```

Remotion's `staticFile()` resolves under `public/` only. Either copy small assets in or symlink — but never reference paths outside `public/`.

## Project layout (use this template)

```
src/<video-name>/
├── package.json                 # remotion + react deps, render scripts
├── remotion.config.ts           # codec, CRF, image format
├── tsconfig.json                # resolveJsonModule: true (for subtitles.json)
├── public/
│   ├── audio/                   # narration MP3s + optional music
│   ├── clips/                   # source video clips
│   ├── cards/                   # brand title cards (gold-on-black)
│   └── <other-assets>/
├── src/
│   ├── index.ts                 # registerRoot(RemotionRoot)
│   ├── Root.tsx                 # <Composition id="..." />
│   ├── theme.ts                 # brand colors + fonts
│   ├── timeline.ts              # SHOT LIST AS DATA — clips/narrations/cards/subtitles
│   ├── subtitles.json           # generated by transcribe-narrations.py
│   └── <Composition>.tsx        # the actual layout component
└── out/                         # rendered MP4s (gitignored)
```

The reference implementation is [src/anchor-doc/](../src/anchor-doc/) — copy this folder as the starting point for every new video, then swap inputs.

## Step-by-step build flow (for a new video)

### 1. Generate inputs

| Input | How |
|---|---|
| Narration script | Write in `<doc>/narration-script.md` per beat |
| Narration audio | TTS via ElevenLabs Daniel voice (`onwK4e9ZLuTAKqWW03F9`) — see `scripts/generate-narration.py` pattern |
| Title cards | `python scripts/generate-title-cards.py` pattern (gpt-image-1, gold-on-black brand) |
| Source clips | yt-dlp from Twitch/YouTube, or wherever your footage lives |

### 2. Probe asset durations

Run the mutagen one-liners from §Pre-flight above. Save the output — you'll reference it constantly while writing `timeline.ts`.

### 3. Scaffold from `src/anchor-doc/`

```bash
cp -r src/anchor-doc src/<new-video-name>
cd src/<new-video-name>
rm -rf out node_modules public/clips/* public/audio/* public/cards/* public/zay-monologue
# Drop YOUR inputs into public/{audio,clips,cards}/
npm install   # if it's a new machine
```

### 4. Edit `src/timeline.ts`

Three arrays + a TOTAL_FRAMES constant:

- `NARRATIONS` — `{ start: sec(N), src: "audio/X.mp3" }` per beat. Tile contiguously.
- `CARDS` — `{ start: sec(N), duration: sec(M), src: "cards/X.png" }` per card.
- `CLIPS` — `{ start, duration, src, trimStartSec?, mute?, ... }` — `duration` ≤ source length.

The composition (`<VideoName>.tsx`) renders each array as a layer. Customize the layout component for video-specific needs (pillar-box, cropping, etc.).

### 5. Generate subtitles

```bash
python scripts/transcribe-narrations.py
# — adapt the NARRATIONS list at the top to match your timeline.ts
# — outputs src/<new-video-name>/src/subtitles.json with timeline-offset cues
```

The DocumentaryTimeline.tsx pattern handles `subtitles.json` automatically — cream serif on translucent black, lower-third, suppressed during card overlays.

### 6. Smoke render the first ~45 seconds

```bash
cd src/<new-video-name>
npx remotion render src/index.ts <CompositionId> out/smoke.mp4 --frames=0-1350
```

Watch the smoke render. Verify: clips don't freeze, narration timing matches expectation, subtitles legible, no JSON import errors.

### 7. Full render

```bash
npx remotion render src/index.ts <CompositionId> out/full.mp4
```

**Time + size expectations** (based on anchor doc, 13:10, 1920×1080, 30fps):
- Render time: ~30-50 min on a typical Windows laptop, all-CPU
- Output size at CRF 18 (current default): ~1 GB
- For upload: re-render at CRF 22 → ~300-400 MB, no visible quality loss after YT re-encode

### 8. Hand off

```bash
# Copy the final into faith-walk-live/<doc-name>/out/ for upload, then
# upload to YT, paste metadata block from publish-plan.md, ship.
```

## What this framework solves vs CapCut/Canva

| Pain | Manual editor | This framework |
|---|---|---|
| Time per cut | 3-5 hours | ~3 hours upfront, then 30-50 min per re-render |
| Iteration cost | Re-do most of the work | Edit timeline.ts, re-render |
| Branded consistency | Re-set colors/fonts every project | `theme.ts` carries across every video |
| Subtitles | Auto-cap then manual fix | Whisper → JSON → burned-in, deterministic |
| Reproducible builds | "Where's my old project file?" | git pull, npm run render |

---

## What it doesn't solve (still needs CapCut/Canva)

- **Pro color grade.** Remotion does CSS filters; for serious DaVinci-grade work, render a v1 from Remotion and do final grade in DaVinci/CapCut.
- **Audio ducking under voice.** Doable but tedious; for music-heavy videos, finish in Canva.
- **"Does this clip feel right here"** — subjective creative decisions still need a human.
- **Kling/Runway video generation.** Remotion composes existing video; it doesn't generate from prompts. Use Kling for AI-generated motion footage, then drop into Remotion.
